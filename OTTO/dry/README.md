# OTTO DRY 수집·운영 적재

독일 OTTO `Trockner` Topseller 검색의 상단부터 매번 새로 탐색해 적격 상품을 최대 300개 수집한다.
제외·상품명 중복 제거 후 main_rank는 1~300까지 연속 부여하고, 같은 행의 bsr_rank는 상위 100개에만 동일하게 부여한다.
main 101위 이후 BSR은 CSV 빈값·DB NULL이며, 별도 BSR 행이나 요청을 만들지 않는다.
목록 API를 실제 검색 끝까지 연속 조회한 뒤, 상품명 선별·카드 보완·기존 상품명 중복 제거로 상위 최대 300개를 확정하고 그 상품만 상세 수집한다.
목록 페이지 사이에 카드·비교표·PDF·평점 요청을 끼우지 않는다. 300개를 확보하면 이후 후보의 상세는 수집하지 않는다.
페이지 수를 고정하지 않으며 실제 검색이 먼저 끝나면 확보한 수량만 저장한다. 290개를 확보했다면 290행이 정상 결과다.
요청 실패·반복 페이지·응답 구조 변경은 검색 끝으로 취급하지 않는다.
제외는 원래의 긴 검색 상품명(`search_title`)만으로 판단하고, 없을 때만 목록 카드명(`listing_title`)으로 보완한다. 카드명은 기존 출력·중복 기준으로 유지하며 긴 제목은 용량 보완에도 보존한다.
API 상품 유형·비교표·PDF로 재제외하지 않는다. 상세 정보는 SKU·용량·투입 방식 추출에만 사용한다. 선별 전 후보 300개에서 먼저 자르지 않으며 제외·중복·카드 누락 뒤의 후보를 계속 확인한다.
확실한 비건조기만 제외한다. 일반 `Trockner`/`Wäschetrockner`나 제품 종류가 불명확한 검색 결과도 정보 부족만으로 제외하지 않고 포함한다. 같은 제목 안의 본품 근거가 충돌하면 포함하고 검수 대상으로 표시한다. 상품명에 세탁기와 건조기 묶음이 명시되면 제외한다.
제외·애매한 판단에는 출처와 최대 500자의 판단 문장을 남긴다. 애매한 상품은 `needs_review=true`와 `ambiguous` 수량으로 표시한다. 건조기 80% 이상·비대상 최대 20% 허용은 검수 목표이며 비대상을 최소 비율로 채우거나 자동 실패 조건으로 사용하지 않는다.
기존 의류 외 전용 건조기 범주인 필라멘트 건조기는 긴 목록 제목의 영어 `Filament Dryer`도 처리한다. 일반 건조기의 기능·동봉 설명 보호는 유지한다.

## 원격 실행 (Windows 명령 프롬프트)

휴대용 건조기 본품(`Portabler Wäschetrockner` 등)과 건조대용 송풍기 본품(`Lüfter für Wäscheständer`)이 제목에 명시되면 제외한다. 일반 `Wäschetrockner` 표시와 함께 있어도 이 명시적 본품 판정을 우선한다. 팬 기능·앱 제어·호환성·동봉 악세사리 설명만으로는 제외하지 않는다.
휴대용 표현은 건조기 본체를 직접 수식하거나 본체의 속성으로 명시된 경우에만 적용한다. `mobile Fernsteuerung`, `tragbare Fernbedienung` 같은 제어·부속품 설명은 건조기의 휴대 여부로 사용하지 않는다. 실제 휴대용 본품에 앱 기능이 함께 있어도 제외는 유지한다.

프로젝트에서 사용하던 Python 환경과 DB 설정을 사용한다. 코드를 원격에 반영한 뒤 실행한다.

```bat
cd /d C:\samsung_dx_seg
call OTTO\run_dry.bat
```

별도 환경변수 설정이 없다면 기본 최대 300개·운영 테이블 `dx_seg.dx_seg_ldy_dryer_retail`로 실행한다.
CLI가 환경변수 `OTTO_DRY_LIMIT`, `OTTO_DRY_TABLE`, `OTTO_DRY_OUTPUT_ROOT`보다 우선한다.
100개만 수집하려면 `call OTTO\run_dry.bat --limit 100`을 사용한다. 이때도 목록은 먼저 확보하며 상세 수집·저장만 최대 100개다.
허용 수량은 1~300이며 범위 밖 설정은 사이트·DB 요청 전에 거부한다. 시작 로그의 `target`과 `bsr_limit`에 실제 적용값을 표시한다.
시작 로그의 `table`을 확인한다. 기존 `OTTO_DRY_TABLE` 환경변수가 있으면 기본 테이블보다 우선하므로 테스트 대상으로 설정돼 있지 않은지 확인한다. 비밀 설정 파일을 출력할 필요는 없다.

전체 실행은 프로젝트 루트에서 `call run_seg_all.bat`를 사용한다.
MMKT TV → OTTO TV → MMKT REF → OTTO REF → MMKT LDY → OTTO LDY → MMKT DRY → OTTO DRY 순서다.
단독 BAT와 통합 실행은 같은 `dry/run.py`를 사용하며 실행당 메일 보고를 한 번만 시도한다.

기존 CSV 재적재: 실행 마지막에 출력된 **실제 CSV 경로**를 넣는다.

```bat
cd /d C:\samsung_dx_seg
call OTTO\run_dry.bat --load-only "C:\samsung_dx_seg\OTTO\dry\data\output\실제_batch_id\otto_dry.csv"
```

CSV와 같은 폴더의 `state.json`을 함께 보존해야 한다. 재적재 시 사이트에 접속하지 않는다.
재적재에는 저장된 확정값을 사용하며 과거 DB 보충을 다시 수행하거나 원본 CSV를 수정하지 않는다.
기존 테스트 CSV를 운영 테이블로 자동 이관하지 않는다. 과거 테스트 결과를 테스트 테이블에 재적재할 때는 `--table dx_seg.dx_seg_ldy_dryer_retail_test`를 명시한다.
완료 또는 실제 결과 부족으로 종료된 CSV만 적재한다. 수집 실패 중간 CSV는 검수용으로 보존하되 적재하지 않는다.
기존 100개 CSV와 과거 `collection_status=shortfall` 상태 파일도 읽을 수 있다.
재적재에서도 main 1~100은 동일 BSR, main 101~300은 빈 BSR이어야 한다. 원래 수집의 오류 통계는 재적재 상태에도 보존한다.
CSV가 변경됐거나 같은 배치가 다른 내용으로 이미 존재하면 중단한다.
동일 배치·동일 내용은 DB 트랜잭션 잠금 후 삽입 0건/중복 N건으로 끝낸다.
DB 적재는 한 트랜잭션으로 처리하며, 별도 테이블 생성·변경·기존 행 삭제는 하지 않는다.

## 결과 파일

기본 폴더: `OTTO/dry/data/output/<batch_id>/`

새 배치는 `o_dry_YYYYMMDD_HHMMSS` 형식이다(예: `o_dry_20261023_123431`).
하루 1회 예약 실행을 전제로 하며 충돌 대기·재시도는 추가하지 않았다. 이미 있는 실행 폴더는 덮어쓰지 않는다.
과거 접미사가 있는 CSV도 재적재할 때 원래 batch_id를 유지한다.

- `otto_dry.csv`: UTF-8 BOM, 요청한 20개 컬럼. 상품 처리마다 저장하며 id는 빈값.
- `state.json`: 배치, 진행 상태, CSV 검증값, 목표/실제/실패 수, 단계별 시간, 빈값 수, DB 결과.
- `run.log`: UTF-8 진행·선택값·실패 요약. 콘솔에도 즉시 출력.
- `diagnostics.jsonl`: 목록 후보·상품명 분류·필드 후보 원본/정규화값·충돌·별점·PDF·오류의 상세 근거.
- 큰 후보·근거 배열은 진단 파일에 한 번 저장하며 로그의 `diagnostic_record`와 진단의 `record_id`가 연결된다. 필드의 최종 출처·선택 원문·선택값과 오류 사유는 콘솔·로그에서도 확인할 수 있다.
- 재적재 로그/상태는 원래 폴더의 `reload_<실행시각>_<고유값>/`에 따로 보존.

종료 코드: 0=목표 도달 또는 실제 검색 종료 후 적재 완료(일부 정보의 NULL은 가능),
2=행 수집 실패·요청/추출 실패·할인율 확인 경고·과거 DB 조회 실패, 3=전체 수집 실패,
4=DB 구조 확인/적재 실패, 5=시작 설정/CSV 검증 실패, 6=수집·적재 정상 완료 후 메일 보고 실패.
메일 실패가 기존 2/3/4 종료 코드를 덮어쓰지 않는다. `collection_exit_code`와 `notification`에 각각 결과를 보존한다.
코드 2에서도 확보한 적격 행은 적재하며, 확인하지 못한 필드는 NULL로 유지한다.
실제 검색 종료로 목표보다 적게 확보한 사실만으로 코드 2를 반환하지 않는다.
새 수집의 정상 종료 상태는 `collection_status=complete`이며 `end_reason=target_reached/actual_search_end`로 원인을 구분한다.
기존 `shortfall_reason` 필드는 실제 검색 종료 시 남은 수량·제외·중복 등을 설명하는 정보로 유지하며, 오류 여부는 별도 실패 통계로 판단한다.
PDF 링크나 명시값을 확인하지 못한 사실만으로 코드 2를 반환하지 않는다. 실제 요청·추출 실패는 다른 출처에서 보완돼도 경고를 유지한다.

진단의 `product_result.row_saved=true`는 해당 행을 CSV에 저장했다는 뜻이다. DB 저장 결과는 `db_status`와 `database`에서 별도로 확인한다.
`status=collected/supplemented`는 기본 수집/보완 수집 경로이며, 정보 완전성이나 오류 없음의 보장이 아니다. `missing_fields`와 `issues`를 함께 확인한다.

| counts 항목 | 의미 |
| --- | --- |
| eligible / output_rows | 확보한 행 / 최종 보존된 CSV 행 수 |
| selected | 상세 수집 전에 상품명 선별·중복 제거를 마친 대상 수 |
| item_failures | 상품정보·식별값 확보 실패로 행을 저장하지 못한 건수 |
| supplemented_items | PDF 또는 상품명 SKU 보완으로 값을 확보한 행 수 |
| incomplete_items | 과거 DB 보충 전 사이트 수집에서 SKU·용량·투입 방식·판매가·평점/평가 수 중 미확보 값이 있는 행 수 |
| request_error_items / extraction_error_items | 최종 출처 처리에 요청/추출 실패가 남은 저장 행 수. 다른 출처의 보완 여부와 별개 |
| price_warning_items | 원가·최종가격은 있는데 할인율이 없는 행 수 |

위 상태는 겹칠 수 있으므로 합해서 상품 수로 해석하지 않는다. 요청별 재시도 이력은 `request_end`에 별도로 보존한다.
DB 구조 확인이 처음부터 실패하면 사이트 수집을 시작하지 않는다.
목록 확보 중 실패하면 상세 수집 전이므로 새 CSV는 0행이다. 확보한 페이지 후보는 진단에 남고 `listing_complete=false`로 기록된다. 상세 수집 도중 실패하면 이미 저장한 각 상품 행을 보존한다.
`listing`의 occurrences는 광고·반복을 포함한 노출 수이며 unique_items/unique_variations와 다르다. API의 count는 기존 페이지 종료 판단에, displayCount는 화면 표시 수 설명에 사용한다. 고정 수량으로 둘을 억지로 맞추지 않는다.
`counts.reviewed`는 실제 선별한 후보 수다. 목표 도달 뒤 미검토 후보가 남을 수 있다. 상세 진행률은 selected를 분모로 하며 원래 목표는 goal로 함께 출력한다.
`request_statistics`는 실제 HTTP 시도 수, 정상 캐시 재사용, 파싱 수, 실패 결과의 재사용을 구분한다. PDF 자식 프로세스의 전달 이벤트도 집계한다.

## 같은 실행 안의 재사용과 저장 범위

카드·비교표는 variation_id, 평점은 기존 리뷰 URL의 상품 ID 단위로 재사용한다. 반환한 사본의 변경이 캐시에 영향을 주지 않는다. 요청 조건과 옵션이 다른 값은 공유하지 않는다.
정상 무평가 0은 유효하게 재사용한다. 비교표·평점의 재시도 소진 결과는 실패 상태와 부분값을 보존해 같은 실행에서 예산을 다시 시작하지 않으며, 정상 캐시 재사용과 구분해 기록한다. 누락된 카드 응답은 정상 카드로 캐시하지 않는다.
PDF는 같은 URI의 열기에 성공한 원문 바이트를 최대 한 문서·기존 다운로드 상한 20,000,000바이트까지 메모리에서 재사용한다. 다른 문서로 바뀌면 해제하고 파일로 저장하지 않는다. 같은 문서라는 이유만으로 다른 옵션의 모델·용량 값을 공유하지 않고 각 호출의 부족 필드를 다시 확인한다. 기존 한 상품 내 재시도·부분값 보존·조기 종료는 그대로다.
매 실행 새 Client를 만들며 전날 가격·평점·CSV를 사이트 수집에 재사용하지 않는다. 안정적인 세 필드의 과거 DB 보충은 아래와 같이 수집 완료 뒤 별도로 수행한다. 상시 사이트 캐시·수집 재개·과거 자료 자동 삭제 기능은 없다.
상품별 원자적 CSV·상태 저장은 유지한다. 후보 추출 결과는 선택과 진단에 재사용하며 PDF에서 새 값이 들어오면 다시 계산한다. 비밀 설정·응답 원문·HTML·PDF·상품별 전체 목록 복사본은 저장하지 않는다.

## 수집 범위와 출처

LDY의 검색 URL 생성·광고 슬롯 배치, 비교표 옵션별 사양 파서, 모델 정리,
최신 평점 파서/검증만 재사용한다. 기존 전체 파이프라인을 실행하지 않는다.
리뷰 본문/페이지 이동, 추천 상품, 배송, 인기, 광고 컬럼, 스티커/OCR,
에너지 소비량을 위한 추출·요청·저장을 하지 않는다.

비교표 이름은 해당 옵션의 상품 링크 안에 있는 제목·부제에서 읽는다. 제목을 확인하지 못하면 `comparison_title_reason`을 남기고 목록명 등 다음 출처를 사용한다. 긴 기능 설명을 제목으로 대체하지 않는다.

SKU: 해당 옵션 비교표 모델 → 해당 옵션 목록에 연결된 PDF → 목록명 전용 추출/공통 형태 보완.
용량: 비교표 긴 제목 → 목록명 → 기존 검색 결과의 긴 제목 → 목록 용량 요약 → 비교표 용량 → 해당 상품 PDF.
투입 방식: 비교표 제목 → Beladung → Bauart → 실제 응답에 제공된 건조기 카테고리 표현 → 해당 상품 PDF의 명시값.
`Front loader`/`Top-loading`만 사용하며, 실제 근거가 없으면 빈값이다.
세탁기 카테고리 요청이나 모든 건조기의 전면 투입 추정은 하지 않는다.
현재 사이트의 건조기 분류 제공 여부는 첫 실제 실행에서 확인해야 한다.

PDF는 SKU/용량/투입 방식 중 앞선 출처에서 부족한 값이 있을 때만 요청한다. 상품당 한 번의 PDF 요청에서 필요한 필드들을 함께 보완한다.
고정 페이지 제한 없이 필요한 필드만 순서대로 확인하며 모두 확보하면 중단한다. SKU만 필요하면 유효한 모델을 찾는 즉시 종료한다. 문서 끝까지 값이 없으면 재요청하지 않고 NULL과 사유를 남긴다.
PDF 모델명은 페이지 안의 명시적 모델 라벨을 순서대로 확인한다. 짧거나 유효하지 않은 후보를 거부한 뒤 같은 페이지의 다음 모델 항목을 확인하고, 유효한 첫 후보를 유지한다. 서로 다른 모델 항목은 합치지 않으며 후보·미채택 사유·선택값·페이지를 진단에 기록한다.
PDF 작업은 Windows에서도 종료 가능한 별도 프로세스에서 실행한다. 한 시도의 요청 단계는 기존 `Client.timeout`(기본 30초), 문서 열기·텍스트 처리는 `PDF_PARSE_TIMEOUT`(기본 30초)을 상한으로 사용한다. 프로세스 시작 시간도 제한에 포함된다. 종료 정리는 최대 2초까지 추가될 수 있다.
요청/문서 처리 실패는 `PDF_MAX_ATTEMPTS=3` 범위에서 최초 시도 후 최대 2회 재시도한다. 각 내부 HTTP 호출은 1회이며 대기는 재시도 전 1초·2초다. 기본 설정에서 최악의 PDF 보완 시간은 약 189초 이내(3×요청 30초+처리 30초+정리 2초, 대기 총 3초)다. 이미 열 수 있었던 PDF는 메모리에서 재사용하고, 열리지 않은 문서나 PDF가 아닌 응답만 새로 요청한다. 과도한 크기에 대한 기존 다운로드 제한은 유지한다.
시간 초과 시 실제 작업 프로세스를 종료하고 앞 페이지에서 확인한 값은 보존한다. 요청 실패·PDF 열기 실패·텍스트 추출 실패·시간 초과·명시값 미확인을 구분한다. 문서 처리 로그에는 확인 페이지, 부족한 필드, 경과시간, 확보 필드, SKU 후보 및 재시도 결과만 남긴다.
투입 방식은 Frontlader·Toplader 등 해당 제품의 명시값만 읽으며 문을 당기는 설명·사진·설치 형태로 추정하지 않는다.
투입 방식 보완으로 PDF 요청이 늘 수 있다. 실제 소요시간은 원격 재수집의 단계 시간으로 확인한다.
텍스트 없는 이미지 PDF나 지원하지 않는 라벨은 빈값/사유로 남기며 OCR은 실행하지 않는다.
기존 공백·모델 정리 후 3글자 이하인 SKU는 DRY에서만 유효하지 않은 값으로 보고 다음 출처를 확인한다. 어디에서도 유효한 모델을 얻지 못하면 SKU만 NULL로 두고 상품 행은 유지한다. 짧은 원본값과 미채택 사유는 진단에 남긴다. 4글자 이상인 값에도 기존 검증을 적용한다. 정상 모델인 `TSA523WP 8kg Active`는 임의로 축약하지 않으며 상품명 보완에서만 시리즈명과 모델 구성 부분을 구분한다. 기존 CSV 재적재는 이 새 선별 규칙으로 과거값을 다시 가공하지 않는다.
savings는 유효한 할인율의 부호를 양수로 정규화한다. 빈값은 유지하며 가격으로 할인율을 새로 계산하지 않는다. 최종가격만 있는 경우는 정상이다.
제목과 사양의 용량 충돌은 선택값과 후보를 진단 파일에 남긴다.
평점은 리뷰 첫 화면 요약만 읽고 실패는 NULL, 검증된 무평가만 0으로 저장한다.
재시도의 부분 응답을 합쳐 양수 별점과 평가 수 0건이 충돌하면 별점은 보존하고 평가 수 두 컬럼은 NULL로 남긴다.
부분 응답끼리 값을 보완해도 한 응답에서 유효한 별점·평가 수가 확인되기 전에는 `failed` 상태를 유지한다.
목록 상품정보의 개별 HTTP 400 오류는 LDY처럼 한 요청 묶음 안에서만 누적하며, 분할 요청은 같은 카운터를 공유한다.
LDY 설정 `OTTO_CROCOTILE_SINGLETON_FAILURE_LIMIT`을 사용하며 기본 3건이면 중단한다. 1~2건은 건너뛰고 다음 묶음에서는 새로 계산한다.
실행 전체 누적은 별도로 `counts.tile_http_400_failures`에 보존한다. 오류 로그에는 묶음별/전체 누적 수와 건너뜀·중단 여부가 기록된다.
최대 HTTP 3회, 시도별 30초 읽기 예산/소켓 제한, DB 연결 10초·쿼리 60초·잠금 15초 제한을 둔다.
느린 작업은 10초 간격 진행 로그를 출력한다. 남은 시간은 지금까지 측정한 처리시간 기준 추정치다.

설정값: country=SEG, account_name=OTTO. item은 상품 ID, sku는 모델명이다.
생성값: main_rank/bsr_rank, calendar_week(`w숫자`, LDY 동일), crawl_datetime(실행 호스트 시각), batch_id.
DB 생성값: id. CSV는 빈칸, INSERT 대상에서는 제외한다.
나머지는 수집/정규화값이며, 가격/할인 표시 단위는 CSV에 유지한다.
DB 숫자 컬럼에는 형식에 맞게 변환하지만 capacity는 kg 보존을 위해 문자형만 허용한다.
시작 시 컬럼·자료형·id 시퀀스/identity·NULL 허용을 확인한다. 수집 실패 가능 필드가 NOT NULL이면 중단한다.
bsr_rank도 NULL 허용이 필수다. NULL 불가이면 `table_requires_nullable:bsr_rank`로 사이트 수집 전에 중단하며 테이블은 자동 변경하지 않는다.

## 수량 확대 후 검수

1. CSV가 정확히 20열·최대 300행인지, main이 연속이고 상위 100개만 BSR이 동일하며 나머지는 NULL인지 확인한다.
2. 제외/애매한 상품과 포함된 상품을 함께 확인해 잘못 포함·제외한 URL을 모은다.
3. SKU가 해당 옵션 모델인지, 용량이 건조 용량인지, 투입 방식에 실제 근거가 있는지 확인한다.
4. 용량 충돌과 별점 failed/unrated, 개별 요청 실패를 진단 파일에서 확인한다.
5. 목표 미달이면 실제 끝/제외/중복/실패 수와 사유를 확인한다.
6. DB 삽입 수, NULL, 재적재 시 삽입 0건을 확인한다.

## 과거 DB·수동 입력값 보충과 메일

수집이 끝나면 `sku`, `capacity`, `loading_type`의 빈값만 현재 적재 대상 테이블에서 보충한다.
현재 정상값은 보존하며, 가격·평점·평가 수·순위는 과거값을 사용하지 않는다.
LDY의 정규화된 item+상품명 일치를 유지하고 country=SEG, account_name=OTTO와 명시적인 `variationId`도 확인한다.
옵션을 확인할 수 없거나 다르면 보충하지 않는다. 제목이 바뀐 상품도 임의로 연결하지 않는다.
현재 배치 및 현재 수집 시각 이후 이력은 제외하고 필드별로 가장 최근의 유효값을 선택한다.
최신 행의 해당 필드가 비었거나 유효하지 않으면 더 이전의 유효값을 확인한다. 수동 입력 여부를 별도로 추정하지 않는다.
필요한 상품·필드만 한 번의 읽기 전용 조회로 가져온다. 연결 10초, SQL 60초, 잠금 15초 제한을 사용한다.
보충 조회는 별도 연결이므로 실패해도 뒤의 INSERT 트랜잭션을 망가뜨리지 않는다. 조회 오류는 코드 2와 메일에 보고하며 새 수집값은 적재한다.
보충 후 CSV·검증값을 먼저 저장하고 DB 적재를 진행하므로 적재 실패 시에도 보충된 결과를 재적재할 수 있다.
`history_backfill`에 보충 상품 수·필드별 건수·미채택 집계·조회 결과를 보존한다.
상품별 참조 배치·선택값은 `run.log`의 `history_field`에 기록하며 `null_counts`는 DB 보충 후의 최종 빈값 수다.
기존 `counts`의 사이트 요청·추출 오류와 사이트 수집 당시 빈값 통계는 보존한다.

기존 `SEG_EMAIL_NOTIFY`, `SEG_EMAIL_DRY_RUN`과 OTTO SMTP 전송 설정을 재사용한다.
메일 활성화 시 정상 종료뿐 아니라 수집·DB 실패 결과도 보고한다. 실제 검색 종료로 300개 미만인 것과 단순 NULL은 실패로 판단하지 않는다.
SMTP는 기존 30초 제한으로 한 번 시도하며 메일 실패 때문에 수집·삽입을 반복하지 않는다.
`state.json`의 `notification`은 disabled/dry_run/sent/failed와 안전한 오류 코드만 남긴다. 별도 보고서 파일은 추가하지 않는다.
메일의 시간은 메일 처리 전 기준이며 최종 상태·로그의 전체 시간에는 메일 처리도 포함한다.
기존 테스트 자료나 과거 DB 행의 수정·이관·삭제는 수행하지 않는다.

## 4차 검수 보완

상품명에서 SKU를 보완할 때 측정 단위와 건조 기능을 조합한 표현이나 전력·프로그램 수를 모델명으로 선택하지 않는다. 정상 비교표·PDF 모델명과 기존 긴 모델명은 그대로 유지한다. 기능 문구를 거부하고 모델을 확보하지 못하면 상품 행은 유지하고 SKU만 NULL로 저장한다.

`2 5 kg`처럼 모호한 숫자 표기는 일부 숫자만 용량으로 확정하거나 소수로 환산하지 않는다. 다음 유효 출처를 사용하고 끝까지 미확보이면 NULL로 둔다. 모델·시리즈 번호 뒤의 정상 용량은 구분한다. PDF도 숫자 구간을 먼저 확인하고, 거부한 뒤 같은 페이지의 다음 용량 항목과 다음 페이지를 확인한다. `pdf_capacity_candidate` 진단에는 페이지·용량 원문 구간·정규화값·미채택 사유를 남기며 전체 PDF 텍스트는 기록하지 않는다.

`Heiztrockner mit Flügeln`처럼 발열식 날개형 건조대 본품을 가리키는 표현은 제외한다. 일반 건조기의 기능·호환·동봉 설명(`inklusive`와 동봉 약어 `inkl.` 포함)은 보호하며, 구체적인 건조기 본품 근거와 충돌하면 검수 대상으로 포함한다. 일반 `Wäschetrockner` 표기만으로 명확한 건조대를 다시 포함하지 않는다. SKU/용량/투입 방식 우선순위·요청 및 PDF 제한·CSV 재적재는 유지한다.

## 6차 검수 보완

비교표는 옵션별 실제 항목 존재 여부를 구분한다. 필요한 값이 없고 항목 자체도 빠졌을 때만, 같은 실행에서 해당 사양을 확인한 옵션을 선두에 넣고 대상 최대 4개를 묶어 보완한다. 기준 옵션이 캐시에 있어도 실제 HTTP 묶음에 포함하며 각 셀의 variation_id로 연결한다. 기준 옵션 값을 다른 상품에 복사하지 않는다. 이미 확보한 값이나 항목은 있으나 명시값이 없는 상품은 이 사유로 재조회하지 않는다. 옵션·필드별 논리적 보완은 실행당 한 번이며 HTTP 재시도·시간 예산은 기존 설정을 사용한다. 기준 미확보·보완 실패 때는 사유를 남기고 기존 PDF 보완을 진행한다. 추가 요청 실패도 실행 오류 통계에 남긴다.

PDF 투입 방식은 해당 제품의 `Form: Frontlader`와 `Front loaded TD` 같은 명시값을 지원한다. `Form` 뒤의 색상 등 다른 항목은 투입 방식 원문에 섞지 않는다. 외형이나 문 위치로 추정하지 않는다. 기존 상부 투입 표준값 `Top-loading`도 유지한다.

PDF 용량은 `Nennkapazität in kg 8,0`, `Nennkapazität Baumwollwäsche: 7,0 kg`을 지원한다. 범위 `1 - 7 kg`이나 모호한 `2 5 kg`을 일부 잘라 단일 값으로 저장하거나 상한·하한·소수로 환산하지 않는다. 거부 후 다음 명시값을 기존 시간 제한 안에서 확인한다. 에너지 단위 값은 용량으로 읽지 않는다.

제목의 `mit Timer, Tragbarer Klein Wärmepumpentrockner`처럼 기능 설명 뒤에 본체 휴대성이 다시 명시된 경우도 기존 휴대용 제외 기준을 적용한다. 앱·리모컨·호환성·동봉 설명과 Mini 단독 표현은 보호한다. 사진 기반 자동 제외·OCR은 추가하지 않는다.
